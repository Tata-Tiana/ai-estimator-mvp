# Каталоги сметы: инструкция

Эта папка нужна, чтобы не смешивать проектные данные, дефолты, цены и строки финальной сметы.

Главное правило: **число само по себе ничего не значит, пока мы не знаем его роль**.

Одна и та же строка в Excel может выглядеть как обычная строка сметы, но внутри системы она может
быть:

- проектным количеством из PDF;
- техническим дефолтом калькулятора;
- бизнес-коэффициентом;
- ценой работы;
- ценой материала;
- фиксированной суммой;
- ручным вводом;
- нулевой структурной строкой;
- контрольной строкой, которая нужна для формы, но не для расчета.

Поэтому один общий "справочник дефолтов" делать нельзя. Нужны разные каталоги.

## Какие каталоги здесь должны быть

### `defaults_catalog.yaml`

Это каталог технических и бизнес-дефолтов.

Сюда входят:

- коэффициенты;
- нормы расхода;
- размеры упаковок;
- кратности закупки;
- длины прутков;
- объемы поддонов;
- расчетные режимы калькуляторов;
- технические константы формул;
- бизнесовые значения по умолчанию, которые Елена подтвердила как дефолтные.

Сюда **не входят**:

- цены работ;
- цены материалов;
- фиксированные суммы строк сметы;
- проектные объемы, площади, длины, количества;
- старые итоговые суммы;
- display quantity из старого Excel;
- числа, которые являются только результатом конкретного проекта.

Пример: `manual_refinement_depth_m = 0.08` для земли — дефолт формулы.

Не пример: `consumables_amount` — это фиксированная сумма строки сметы/цена, а не дефолт формулы.

### `estimate_line_catalog.yaml`

Это каталог строк финальной сметы.

Сюда входит:

- какие строки должен вернуть раздел;
- код строки;
- русское название;
- единица измерения;
- формула количества;
- откуда берутся leaf inputs;
- какие price keys нужны;
- может ли строка быть нулевой;
- является ли строка обычной, контрольной или структурной;
- есть ли она в текущем калькуляторе или пока только в Excel-шаблоне.

Этот каталог не хранит реальные количества и реальные цены проекта.

### Price registry / fallback prices

Цены живут отдельно от этих каталогов.

Цена может прийти из:

- price registry;
- fallback;
- Google review workbook, лист `02_Цены себестоимости`;
- ручной правки Елены;
- supplier/manual input, если это не обычная единичная цена.

Даже если в старой смете цена выглядела как "дефолтная", технически это не `DEFAULT`, а `PRICE` или
`FIXED_PRICE`.

**Правило (2026-07-14): любая цена всегда ищется сначала в прайсе, и только потом идёт
fallback.** Это не поведение конкретного калькулятора, а общий механизм `resolve_price()`
в `experiments/pricing/price_reader.py` — порядок всегда: `project_price_overrides` →
`price_registry` → fallback из input.json. Даже для совсем нового `price_code`, которого
ещё нет в реестре, резолвер сначала проверяет реестр и только потом берёт fallback (с
явным warning). Это значит: как только Елена впишет реальную цену в реестр, калькулятор
подхватит её на следующем прогоне сам, без правки кода — но **только если** запуск идёт в
режиме `pricing.mode: price_registry_with_fallback`. Если этот блок не указан явно, режим
по умолчанию — `locked_case_prices`, который в реестр вообще не смотрит и берёт число
прямо из input.json навсегда. Любой adapter/`build_input.py`, который в будущем будет
собирать вход калькулятора из проверенной Google-таблицы, обязан явно ставить
`price_registry_with_fallback` — иначе добавление цены в реестр ничего не изменит. См.
`experiments/pricing/README.md` для деталей механизма.

## Как классифицировать поле

Перед тем как добавить любое поле в каталог, нужно ответить на вопросы.

### 1. Это проектное количество?

Если значение должно прийти из PDF/chat JSON или быть проверено на листе `01_Проверка проекта`, это
не дефолт.

Класс:

```text
AUTO_PROJECT
```

Примеры из земли:

- `pit_area_m2`;
- `pit_excavation_depth_m`;
- `sand_base_volume_m3`;
- `trench_volume_m3`;
- `geotextile_area_m2`;
- `geotextile_laying_area_m2`;
- `communications_length_m`.

### 2. Это цена?

Если значение умножается как цена за единицу или фиксированная сумма строки сметы, это не дефолт.

Класс:

```text
PRICE
```

Примеры из земли:

- `axis_marking_work_unit_price`;
- `excavator_material_unit_price`;
- `manual_excavation_work_unit_price`;
- `sand_material_unit_price`;
- `consumables_amount`.

Важно: `consumables_amount` выглядит как "расходники по умолчанию", но в калькуляторе земли это
фиксированная сумма строки сметы. Она идет через price/fallback/manual review, а не через
`defaults_catalog.yaml`.

### 3. Это техническая формула или бизнесовый коэффициент?

Если значение нужно формуле и не должно извлекаться из PDF, это дефолт.

Класс:

```text
DEFAULT
```

Примеры из земли:

- `excavator_productivity_m3_per_shift`;
- `manual_refinement_depth_m`;
- `trench_width_m`;
- `sand_compaction_coeff`;
- `sand_truck_step_m3`;
- `geotextile_overlap_coeff`;
- `geotextile_roll_area_m2`;
- `axis_marking_shifts`;
- расчетные режимы `*_calc_method`.

### 4. Это считается из других значений?

Если значение не вводится человеком и не приходит из PDF, а получается из других полей, это
автоматический расчет.

Класс:

```text
AUTO_CALCULATED
```

Пример из земли:

```text
manual_excavation_quantity_for_estimate_m3 =
pit_area_m2 * manual_refinement_depth_m + trench_volume_m3
```

### 5. Это ручное решение?

Если значение не извлекается из PDF и не является универсальным дефолтом, но Елена должна его
подтвердить или ввести, это ручной ввод.

Класс:

```text
MANUAL_REVIEW
```

Для других разделов сюда часто попадают кран, доставка, бетононасос, фиксированная логистика,
технический надзор, если они не считаются формулой.

## Нулевые строки

Ноль бывает разный. Нельзя просто сказать "если 0, удалить".

В `estimate_line_catalog.yaml` у строки есть `zero_policy`.

Возможные значения:

```text
not_expected
```

Строка обычно не должна быть нулевой. Если ноль появился, это повод проверить цену или количество.

```text
allowed
```

Нулевая сумма допустима. Строка может оставаться в смете.

```text
requires_review_if_zero
```

Ноль допустим технически, но Елена должна проверить, что это не пропущенная цена.

```text
structural_zero
```

Строка нужна для структуры Excel/сметы, но сейчас не участвует в расчете.

```text
disabled_if_zero
```

Если количество или сумма ноль, строку можно не выводить, если это подтверждено правилами раздела.

Пример из земли:

- `sand_manual_moving` может быть нулевой, если цена не задана или работа не нужна.
- `axis_marking` не должна тихо стать нулевой, потому что это обычная рабочая строка с ценой.
- `technical_supervision_zero`, `overhead_zero`, `profit_zero` — это структурные кандидаты из Excel,
  но не строки текущего earthworks-калькулятора.

## Где искать значения для каталогов

Искать нужно в таком порядке.

### 1. `section_contract.yaml`

Первый источник для структуры:

- `review_parameters`;
- `price_keys`;
- `defaults`;
- `auto_calculated`;
- `supplier_inputs`;
- `estimate_lines`.

Для земли:

```text
experiments/full_estimate_review_pipeline/sections/earthworks/section_contract.yaml
```

### 2. Код калькулятора

Калькулятор — ground truth по реальным input names и реальным estimate line codes.

Для земли:

```text
experiments/earthworks_calculator/earthworks_calculator.py
```

Особенно смотреть:

- dataclass input;
- default values;
- `calculate_internal_estimate_lines`;
- формулы количества;
- `price_code`.

### 3. Adapter review -> calculator

Adapter показывает, что реально читается из review workbook и как собирается input.

Для земли:

```text
experiments/earthworks_review_to_calculator/calculator_input_builder.py
experiments/earthworks_review_to_calculator/constants.py
```

Там видно, что:

- дефолты земли сейчас живут в `GENERIC_CALCULATOR_DEFAULTS`;
- цены собираются из rows sheet 02;
- `consumables_amount` отдельно вынимается из цен;
- `communications_length_m` имеет аккуратную legacy/pipe-items семантику.

### 4. Formula-ready builder

Formula-ready показывает, какие строки реально уходят в финальную Excel-смету и какие helper cells
нужны.

Для земли:

```text
experiments/earthworks_review_to_calculator/build_formula_ready_result.py
```

Это важно для строк, где количество считается не напрямую, а через helper cells.

### 5. Старые прогоны и тесты

Старые `input.json`, `result.json`, `result.md`, Excel-файлы и скриншоты можно использовать только
как подсказку:

- какие строки были в смете;
- какие price keys использовались;
- какие дефолты раньше были нужны;
- где искать значение в коде.

Нельзя автоматически копировать оттуда числа в production catalog.

Если число найдено только в старом ЮСВ-прогоне, статус должен быть:

```text
needs_elena
```

или:

```text
candidate_from_reference_run
```

а не `confirmed`.

### 6. Июньская таблица Елены

Если в июньской таблице явно отмечено, что поле является дефолтом, ручным вводом или расчетным
значением, это сильный источник классификации.

Для таких значений в каталоге нужно писать:

```yaml
source_note: "Elena June manual/default review"
confidence: confirmed
```

Если такой таблицы под рукой нет или значение не найдено, писать честно:

```yaml
confidence: needs_elena
```

## Как использовать числа из ЮСВ

Можно:

- посмотреть, какие строки были в старой смете;
- понять, какие поля требовал калькулятор;
- найти старые defaults/fallbacks;
- сравнить форму результата с новым pipeline.

Нельзя:

- брать проектную площадь/объем/длину/количество как дефолт;
- брать старую цену как production price без price registry/Елены;
- брать старый итог строки как expected total;
- брать display quantity как расчетную величину;
- хардкодить имя проекта, PDF, страницу, адрес или старый путь.

Безопасная формула:

```text
ЮСВ показывает, где искать правило.
ЮСВ не является правилом сам по себе.
```

## Как добавлять новый раздел

Для каждого раздела:

1. Открыть calculator.
2. Выписать все `estimate_lines`.
3. Для каждой строки записать формулу количества.
4. Разложить leaf inputs по классам:
   - `AUTO_PROJECT`;
   - `DEFAULT`;
   - `AUTO_CALCULATED`;
   - `PRICE`;
   - `SUPPLIER_INPUT`;
   - `MANUAL_REVIEW`.
5. Добавить технические дефолты в `defaults_catalog.yaml`.
6. Добавить строки сметы в `estimate_line_catalog.yaml`.
7. Не добавлять цены в `defaults_catalog.yaml`.
8. Не добавлять проектные значения из ЮСВ.
9. Для сомнительных чисел ставить `status: needs_elena`.
10. Проверить, что `section_contract.yaml`, calculator и catalog говорят одними кодами.

## Минимальный preflight перед запуском калькулятора

Перед запуском adapter/calculator нужно проверить:

- все `AUTO_PROJECT` значения пришли из review workbook или явно отмечены как missing/manual;
- все `PRICE` values найдены в price registry/fallback/manual review;
- все `DEFAULT` refs есть в `defaults_catalog.yaml`;
- все `MANUAL_REVIEW`/`SUPPLIER_INPUT` значения заполнены или отмечены как blocking;
- каждая строка из `estimate_line_catalog.yaml` либо возвращается калькулятором, либо имеет
  понятный статус `structural_zero`, `disabled`, `not_in_current_calculator`.
