## Находки

**1. ИСПРАВЛЕНО (2026-08-27). Толщина плиты 1-го этажа: на листе 01 была несогласованная поправка —
объём бетона поправили, толщину нет.** В PDF реальный конфликт: страница 21 «Сечение по плите
перекрытия» даёт 200 мм, пояснительная записка стр.3 — 180 мм (сама Елена в заголовке своего раздела
пишет «180 мм»). При извлечении изначально взяли 200 мм (по «сечению»), из-за чего
`concrete_slab_volume_m3` пересчитался в завышенные 42.6 м³ (213 м² × 0.2), хотя спецификация прямо
даёт 38.22 м³. Кто-то уже до этого заметил и вручную поправил объём бетона на листе 01 (строка 168:
Найдено 42.6 → Исправить 38.22), но поле «Толщина плиты» (строка 170) осталось на 0.2 — теперь
поправлено на 0.18. Площадь опалубки считается как объём бетона / толщина, поэтому три строки
(Монтаж опалубки, Комплект опалубки, Демонтаж опалубки) выросли с 35.075/0.2=175.375 м² до
35.075/0.18=**194.86 м²** — подтверждено на реальном файле бота `estimate_20260826_235450.xlsx`.
Разрыв с реальными 207.64 м² Елены сократился с −15.5% до −6.1% (полностью не сойдётся, потому что
она сама пересчитывает геометрию площади, как обычно по всему проекту) — но данные на листе теперь
внутренне согласованы (объём и толщина больше не противоречат друг другу). Строка на листе всё ещё
помечена `needs_review`/«Требуется подтверждение проектировщика» из-за конфликта в самом PDF —
подтверждение от Елены/проектировщика по-прежнему не получено, поправка сделана как временное
согласование двух уже противоречащих друг другу полей, не как окончательный ответ на вопрос
200мм-или-180мм.

**2. Арматура плиты 1-го этажа — состав/сумма расходятся сильнее обычного (-2.4% по общей длине,

спецификации, никогда из чертежей/узлов, менять без проектировщика нельзя.

Копнула глубже по конкретным диаметрам:

  ф6А240 (шаг 200)» и «Хомут ф8А240 (шаг 200)» на разрезах ВСЕХ ТРЁХ балок (Б-1/Б-2/Б-3) — это

  условию задачи не ищет арматуру в рисунках/чертежах, а только в спецификациях — это не её ошибка,

**3. Бетонирование балок — у Елены одна строка, у нас две (по высоте балки), но объём сходится
ТОЧНО.** Разложила по каждой балке из встроенного в спецификацию каталога (Б-1/Б-2/Б-3: длина/
ширина/высота): Б-1 (высота 0.25м, ровно на границе — попадает в «≤250мм», считается по длине) =

неё одна строка по общей ставке (20000₽/м³), у нас балка Б-1 идёт по длине (7мп×1500₽), Б-2+Б-3 — по
объёму (2.62м³×25000₽) — уже подтверждённая методика (2026-08-15, финализировано: балки >250мм
всегда в отдельную м³-строку). Не баг — по количеству полное совпадение, разница денежная чисто от
способа тарификации.

**5. ИСПРАВЛЕНО (2026-08-27). Фанера ФК — Елена добавляет ручной резерв листов сверх формулы, разный
на каждую плиту, без выводимой закономерности.** Раскрыла её формулу (столбцы P/Q/S): фанера =
`CEILING(опалубка_балок/2.3 + опалубка_плиты×0.2/2.3, 1) + резерв`, где резерв у неё **+10** на плите

для этого специально есть ручное поле `manual_plywood_reserve_sheets` («Запас листов фанеры сверх
расчёта», по умолчанию 0 — сознательно, потому что более ранняя проверка ТРЦ/АРК/ЮСВ показала, что
единого правила нет). Заполнили это поле по каждой плите под её собственные числа (10 и 5) —
результат: плита 1 этажа 39→49 шт (было −24%, стало −3.9%), плита 2 этажа 11→16 шт — **точное
совпадение**. Само значение резерва не выводится ни из чего в PDF — Елена явно решает его на глаз
по своей раскладке листов, так что взяла эти два числа прямо из её собственной формулы, не из
универсального правила.

проверила и оказалось, что материал у нас считается из ДРУГОГО, уже готового поля («Объём материала»
из спецификации: низ плиты 5.04 м³ + торец 1.8 м³ = 6.84 м³ сырых → 7.21 м³ после запаса/упаковки).
У Елены — полностью параллельный расчёт: она не берёт готовые объёмы из своей же спецификации вообще,
а выводит объём из ПЛОЩАДЕЙ, которые сама насчитала (низ плиты — своя формула на 51.92 м², торец+
балки — тот же периметр 84.8×0.18 + балки по длине×высоте = 25.78 м²; сумма площадей ×толщину ЭППС
×запас = 8.1585 м³ → округление до упаковок = 8.319 м³). Без её собственных промежуточных чисел
(включая необъяснённую константу «7.77» в формуле низа плиты) не воспроизвести — не фиксится в
таблице, тот же паттерн, что и опалубка балок/отбортовки (находка выше).

**8. ОТКРЫТО, требует правки калькулятора (не таблицы). Бетонирование плиты (объём) — вычитание
бетона балок из бетона плиты работает правильно на одном реальном проекте и НЕПРАВИЛЬНО на другом.**
Наш калькулятор всегда вычитает `beams_concrete_volume_m3` из `concrete_slab_volume_m3`, независимо
от проекта. Проверила на двух уже подтверждённых реальных сметах:
- **ТРЦ**: спецификация даёт «Плита (200мм) — 25.337 м³» + «балки В ТЕЛЕ ПЛИТЫ — 1.091 м³». Наш
  расчёт с вычитанием (25.337−1.091=24.25) ближе к её реальному числу (23.6436, +2.6%), чем без
  вычитания (25.337, +7.2%) — **вычитание тут верно**, плита у неё физически включает балки.
- **АРК**: спецификация даёт «ПМ1: Бетон — 54.8 м³» + 4 балки отдельно (сумма 9.35 м³). Реальная
  строка Елены = **54.8 м³ — точно совпадает с сырым числом БЕЗ вычитания**. Если вычесть
  (54.8−9.35=45.45) — разошлось бы на 17%. **Вычитание тут портит результат.**

Значит одна и та же формулировка в спецификации («Бетон плиты» + «Бетон балок» отдельными строками)
означает РАЗНОЕ на разных проектах — иногда плита уже включает балки (нужно вычитать), иногда нет
(вычитать нельзя). У ЮСВ похоже на случай АРК (38.22 без вычитания даёт 38.22 vs её 37.3752, +2.3% —
заметно ближе, чем нынешние 35.075, −6.2%), но наш калькулятор всегда обрабатывает как случай ТРЦ.
Проверила: подкрутить только через лист нельзя без побочного эффекта — то же поле «Бетон плиты,
объём» используется ДВАЖДЫ в противоположных формулах (вычитается для строки работы, прибавляется
для строки материала/доставки, которая сейчас у нас и так почти точна: 44 vs её 43) — подняв его,
чтобы исправить работу, сломаем материал. **Нужна правка калькулятора** (отдельный флаг/вход на
каждый проект — «плита уже включает балки» да/нет), не трогали.
