# Проверка каталогов стен P6 и пакета парсинга

Проверено 2026-09-18. Каталоги обновлены по текущему коду калькулятора и адаптера,
с дополнительной сверкой рабочего пакета парсинга. Числа конкретного проекта
остаются в extraction, review workbook и результатах расчёта.

## Рабочий пакет парсинга

Пакет: `experiments/chat_extraction_poc/dist/claude_chat_extraction_pack.zip`.
Все 7 файлов побайтово совпадают с исходниками, JSON/YAML читаются без ошибок.

| Файл | Проверка для стен |
| --- | --- |
| `data/calculator_targets_compact.json` | Раздел `load_bearing_walls_lintels_p6`, только повторяемые группы; старые scalar targets запрещены |
| `data/target_aliases_ru.yaml` | Все 5 групп стен относятся к P6 |
| `data/section_guide.json` | Зоны стен, блоки, перемычки и арматура; перегородки исключены |
| `data/unit_normalization_guide.json` | Есть м3, м2, мп, шт и кг; `mixed` предусмотрен для повторяемых строк |
| `schemas/claude_extraction_output_schema.json` | Описание формы JSON, не строгая JSON Schema; поддерживает объекты групп и исходный видимый текст |
| `prompts/claude_estimate_extraction_prompt.md` | В ZIP находится текущая версия исходного prompt |
| `README_FOR_CHAT_UPLOAD.md` | В ZIP находится текущая инструкция загрузки |

Группы: `wall_zones`, `wall_block_items`, `wall_chasing_rebar_items`,
`lintel_items`, `lintel_rebar_items`. Они соответствуют группам контракта P6
и затем собираются адаптером во вложенные `wall_zones[]`.
Демонтаж опалубки не является отдельным PDF target: калькулятор выводит его
из площадей опалубки монолитных перемычек.

Другой ZIP, `four_step_parsing_test/dist/four_step_chat_extraction_pack.zip`,
содержит старые версии части справочников. Эксперимент закрыт 2026-07-28,
что явно указано в его текущем README. Этот архив не является рабочим источником;
его содержимое не обновлялось в рамках этой проверки.

## Фактическая цепочка расчёта

`review_workbook -> core.job_runner.run_section -> контракт P6 -> нормализация и цены
-> sections/load_bearing_walls_lintels_p6/build_input.py -> калькулятор P6
-> estimate_lines JSON -> Excel-экспорт`.

Каталоги не исполняются этой цепочкой. Контракт даёт большую часть дефолтов;
ещё 6 полей поступают из `P6Defaults`: параметры пескобетона (3), длина U-блока,
расход и минимум клей-пены. Количества лесов адаптер читает из ручных полей
review-файла; если поля пусты, использует 2 комплекта и 2 м3 пиломатериала.

Значимые правила текущего калькулятора отражены в каталогах:

- Объединение нескольких зон парапета перед расчётом.
- Объединение блоков по материалу внутри зоны до округления по паллетам.
- Подбор стандартной цены/паллеты по плотности и сечению блока; исправление D400 150x250 при подборе на D500.
- Объединение клея обкладки с предшествующей обычной зоной до округления мешков.
- Объединение арматуры по зоне, назначению, классу и диаметру до округления хлыстов.
- Каркас перемычек по поставочной длине арматуры; нулевая внутренняя ставка.
- Общий заказ бетона U-блоков и монолитных перемычек по зоне, с запасом и округлением вверх до целого м3.
- Разные партии доставки блоков и крана; отдельный кран парапета.
- Контрольные монтаж/демонтаж опалубки; фанера целыми листами, пиломатериал вверх по 0,1 м3.
- Утепление только фактически утеплённых частей; ЭППС по упаковкам, отдельное display-округление.
- Расходники по сырой прямой себестоимости до мусора и технадзора.
- Технадзор как денежный бизнес-дефолт контракта, а не цена из реестра.

## Изменения каталогов

В `estimate_line_catalog.yaml` добавлен актуальный раздел P6: **34 семейства строк**
с реальными шаблонами кодов, названиями, единицами, формулами и условиями появления.
Общий фиксированный счётчик строк не задаётся: количество зависит от данных.

В `defaults_catalog.yaml` добавлены **24 технических дефолта P6**.
Количество лесов и денежная сумма технадзора отделены от технических дефолтов.
Разделы `load_bearing_walls_lintels` сохранены как `legacy_reference_only`,
с `active_in_full_estimate_export: false` и ссылкой на P6. Убраны две ошибочные
записи демонтажа в старом формате, добавленные ранее 2026-09-18.

## Проверки и ограничения

- YAML обоих каталогов проверен на корректность и повторяющиеся ключи.
- Все 24 значения сверены с dataclass; все соответствующие дефолты контракта совпали.
- Ссылки на технические дефолты и семейства строк разрешаются.
- На входных данных АРК, ТРЦ и ЮСВ проверены шаблоны кодов, названия, единицы и статические price codes.
- Все 34 семейства встретились в прогонах; условная доставка металла дополнительно проверена с положительным входным количеством.
- Проверены отсутствие перемычек, нулевая опалубка, бетон без заданной длины и совместный расчёт U-блоков/монолитных перемычек с округлением материалов.
- `git diff --check` прошёл.

На сохранённом `calculator_input` АРК из `extraction_output_7_20260910_131118/section_results`
пересчёт добавил только `main_walls_lintel_formwork_dismantling`, **3,93 м2**.
Существующие строки совпали полностью, итоговая себестоимость сохранилась.

Текущий `review_workbook_v2.xlsx` в той же папке содержит **2 комплекта лесов и 2 м3**
пиломатериала. В результатах, использованных для сметы `160829`, было **1 комплект
и 1,5 м3**. Поэтому новый расчёт из текущего workbook отличается ещё по лесам
и расходникам. Эти проектные значения не исправлялись.

Сохранённый результат ТРЦ `output/trc_v54_check` также отличается от пересчёта
по уже существующим текущим правилам резки U-блоков и округления пиломатериала.
Старые результаты не использованы как источник формул; каталог описывает текущий код.

Калькулятор, адаптер, контракт, проектные workbook/сметы и рабочий ZIP в рамках
этого обновления каталогов не менялись. В контракте остаются исторические
`draft`/owner notes и неполное описание некоторых семейств строк; фактический
состав строк каталога проверен непосредственно по калькулятору.
