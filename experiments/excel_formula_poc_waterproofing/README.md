# Waterproofing Formula Excel POC

Это изолированный POC Excel-экспорта для раздела "Гидроизоляция, утепление бортов плит".

POC не меняет основной проект и не внедряется в:

- `box_calculator`;
- `input_builder`;
- `live-pricing`;
- рабочие калькуляторы;
- demo Excel по фундаментной плите.

## Цель

Проверить, что можно сделать Excel-смету в привычном сметном виде:

- основной лист содержит смету;
- справа от сметы есть построчные helper-ячейки для проверки количеств;
- цены остаются в самой сметной таблице;
- формулы записаны обычными A1-ссылками: `=P12*Q12`, `=J12*K12`, `=SUM(...)`;
- named ranges и технические Python-переменные не используются.

## Источники

POC работает только от frozen fixtures:

```text
fixtures/input.json
fixtures/expected.json
fixtures/waterproofing_result.json
fixtures/price_registry_snapshot.xlsx
fixtures/brick_house_logo.png
```

Файл `price_registry_snapshot.xlsx` сохранён как snapshot, но готовый Excel не показывает отдельный рабочий лист `Прайс`.

## Что внутри Excel

Файл:

```text
output/waterproofing_formula_demo.xlsx
```

Видимый лист:

- `Смета`.

На листе `Смета`:

- `A:I` — белая зона сметы;
- `J:O` — серая внутренняя зона сметы;
- `P:V` — правое серое вспомогательное поле.

Правая зона `P:V` — не отдельная панель и не прайс. Это построчное продолжение сметы: вспомогательные значения стоят на той же строке, к которой относится строка сметы.

Примеры:

- строка гидроизоляции: `P12 = 81`, `Q12 = 0.3`, `R12 = P12*Q12`;
- строка праймера: `S13 = P13*Q13/R13`;
- строка мастики: `T14 = P14*Q14*R14/S14`;
- строка Пеноплэкса: `P16 = 0.2776`, `Q16 = J15*0.1*1.05`, `R16 = Q16/P16`;
- строка клей-пены: `R17 = P17/Q17`.

В правой зоне нет заголовков типа "РАСЧЁТНОЕ ПОЛЕ", "Праймер", "Мастика", "ЭППС". Она выглядит как рабочие helper-ячейки в строках сметы.

Строки логистики, расходных материалов и итоговая строка не дублируются справа: для них в P:V нет параметров расчёта количества.

Цены находятся в колонках:

- `K` — материалы / механизмы, за единицу;
- `M` — работы, за единицу.

Белая зона технически копирует серую формулами `=J12`, `=K12`, `=L12` и т.д.

Клиентская часть не считается. Коэффициенты клиента, НР/СП, налоги и прибыль не добавляются.

## Ожидаемый итог

```text
materials = 33961
works = 17255
section_total = 51216
```

`openpyxl` не пересчитывает формулы Excel, поэтому скрипт проверяет структуру workbook:

- файл создан;
- есть видимый лист `Смета`;
- серая зона содержит формулы;
- белая зона ссылается на серую;
- справа есть построчное вспомогательное поле `P:V`;
- в правом поле нет прайса и `price_code`;
- в правом поле нет отдельной панели с заголовками разделов расчёта;
- цены находятся в колонках `K` и `M`;
- Пеноплэкс считается от raw-количества `J16 = ROUNDUP(R16,0)*P16`, а не от округлённого display;
- в формулах нет технических имён параметров.
