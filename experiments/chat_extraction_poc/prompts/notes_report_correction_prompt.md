ИСПРАВЛЕНИЕ JSON ПО ТЕХНИЧЕСКОМУ ПРИЛОЖЕНИЮ (код-отчёт)

У тебя есть в этом же чате:

1. исходные PDF-файлы проекта;
2. уже сформированный extraction JSON;
3. техническое приложение — файл `code_notes_report_*.txt`, собранный кодом (не нейронкой) из этого JSON.

Приложение — не служебная записка для сметчика. Это список технических несоответствий, которые программа нашла напрямую в структуре JSON: повторяющиеся/отсутствующие `code` в repeated group, значения, взятые из запрещённого источника, конфликты scalar-полей, и т.п. Каждый пункт помечен статусом (`semantic_error`, `needs_review`, `missing_code`, `raw_table_rows`, `not_required_alt`, `conditional_absent_ok`, `diagnostic_only`).

ЗАДАЧА

Пройди по приложению пункт за пунктом и реши каждый **только по этому JSON и исходным PDF** — не придумывай значения.

Для каждого пункта:

- `semantic_error` — это нарушение уже задокументированного правила (например: несколько строк одной repeated group совпадают по floor/component/steel_class/diameter и не имеют уникального `code`; или значение сопоставлено с target_code, для которого этот источник строки прямо запрещён). Исправь JSON: добавь недостающие `code` (уникальные, по смыслу строки — не порядковый номер), убери запрещённое сопоставление, разведи перепутанные значения. Если для решения не хватает данных из PDF — не исправляй молча, оставь как есть и явно об этом скажи в ответе.
- `needs_review` — прочитай соответствующие страницы PDF заново. Если можешь надёжно снять конфликт/неоднозначность по PDF — сделай это и явно опиши, что изменил. Если нет — оставь needs_review как есть, ничего не выдумывай.
- `missing_code` (список «Не найдено в JSON» в конце каждого раздела) — проверь по PDF, есть ли эти данные вообще. Если данные в PDF реально отсутствуют — не трогай. Если нашёл — добавь как `found` с указанием страницы/источника.
- `raw_table_rows`, `not_required_alt`, `conditional_absent_ok`, `diagnostic_only` — это не задачи на исправление, а объяснение уже принятого решения. Не трогай эти строки, если явно не увидишь в PDF ошибку в самом объяснении.

ЧЕГО НЕ ДЕЛАТЬ

- Не переписывай JSON целиком «с нуля» — редактируй только то, что указано в приложении.
- Не меняй поля/секции, которых нет в приложении, даже если кажется, что их можно улучшить.
- Не рассчитывай итоговые значения (сумма зон, объём и т.п.), если в PDF нет явного готового проектного итога — так делать запрещено правилами извлечения.
- Не удаляй `needs_review`/`candidates`, если сомнение реально осталось после повторной проверки PDF.

РЕЗУЛЬТАТ

1. Сохрани исправленный JSON отдельным файлом (не перезаписывай исходный, дай новое имя с суффиксом, например `_corrected`).
2. В чат выведи короткий список: что именно исправлено (пункт из приложения → что сделано), что осталось без изменений и почему.
3. Не публикуй полное содержимое JSON в чат — только ссылку на файл и список изменений.
