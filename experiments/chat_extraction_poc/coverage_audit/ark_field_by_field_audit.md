## Служебная записка — 7 пунктов без объяснения, почему и как чинить

Проверила: у всех 7 «потерянных» needs_review-элементов **notes в самом JSON уже есть, содержательные
и понятные** (см. таблицу ниже) — то есть проблема не в том, что модели нечего было писать, а в том,
что при составлении итоговой записки она не прошлась по каждому needs_review элементу и не вынесла
его отдельным пунктом. Это системная недоработка именно шага "собрать записку", а не шага извлечения.

| Код | Что уже есть в notes JSON (могло бы стать пунктом записки) |
|---|---|
| `beam_items` | Б4/Б4-1 разной ширины (300/400мм) идут одной объединённой строкой длины/бетона |
| `communications_pipe_items` | Дублирующая таблица ЭО на листе — проверено, не задвоено |
| `floor_1_lintel_insulation_eps_volume` | ЭППС указан только для ПБ1, для ПБ2 отдельно не дано |
| `floor_slab_1_edge_eps_work_length` | Периметр плиты дан, но не отдельно длина торцов балок |
| `floors_count` | Отдельного 2-го этажа нет, зона второго света — как floor_2 masonry |
| `geotextile_laying_area_m2` | Нет отдельной строки работ, продублировано количество материала |
| `waterproofing_area_m2` | Не отдельная строка, переиспользована площадь опалубки плит |

**Правка промпта**: в разделе про служебную записку добавить явный завершающий шаг-чеклист:
«прежде чем считать записку готовой, пройдись по каждому `needs_review` элементу КАЖДОГО раздела и
убедись, что для него есть отдельный пронумерованный пункт в записке (логически близкие можно
объединять в один пункт, но ни один needs_review не должен остаться совсем без упоминания)». Сейчас
такого явного финального чек-листа в промпте, судя по всему, нет — есть общее указание выносить
конфликты в записку, но нет шага-проверки полноты в конце.
