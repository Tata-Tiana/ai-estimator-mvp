# Шаг 1 — прочитать PDF и выписать сырые таблицы проекта

Используй этот промпт в отдельном чате. В этот чат загружается только один PDF
проекта: либо КР1 / ниже нуля, либо КР2 / выше нуля.

Не загружай в этот чат:

- `calculator_targets_compact.json`;
- `target_aliases_ru.yaml`;
- `section_guide.json`;
- `unit_normalization_guide.json`;
- финальную schema extraction.

На этом шаге нельзя думать о смете, `target_code` и калькуляторах. Твоя задача —
сделать честную машиночитаемую перепись проекта: страницы, штампы, таблицы,
спецификации, ведомости, легенды, графические маркеры и важные подписи рядом с
таблицами.

## Что нужно сделать

1. Пройти PDF постранично.
2. Для каждой страницы определить:
   - номер страницы PDF по счётчику PDF;
   - номер листа из штампа, если виден;
   - общее количество листов из штампа, если видно;
   - название листа;
   - короткий сырой текст штампа/титула.
3. Выписать все таблицы, спецификации, ведомости и табличные блоки подряд.
4. Сохранять колонки как они видны в проекте. Не перепридумывать заголовки.
5. Сохранять исходные ячейки, `raw_text`, ГОСТ/СТО, марки, толщины, размеры,
   примечания и единицы.
6. Если строка различается графическим маркером, штриховкой, цветом или
   обозначением в первой колонке, сохранить этот маркер и связь с легендой через
   `legend_ref`.
7. Если таблица нечитаема, размыта, наложена на чертёж или колонки разъехались,
   не угадывать: сохранить как получилось и добавить предупреждение.
8. Если на листе есть таблица спецификации и рядом чертёж/схема/узел с тем же
   материалом или слоем, сохрани оба места: строку спецификации и подпись на
   чертеже. Ничего не выбирай на этом шаге.
9. Если текстовый слой страницы выглядит как каша, попробуй прочитать страницу
   визуально по картинке. Если визуальная проверка не сработала, запиши это в
   `extraction_warnings`.

## Важные типы таблиц

Обязательно выписывай как таблицы, если они есть:

- маршруты траншей;
- спецификации труб/коммуникаций;
- спецификации арматуры;
- спецификации Ж/Б балок;
- спецификации перемычек;
- спецификации газобетонных блоков;
- спецификации гидроизоляции и отсечной гидроизоляции;
- спецификации плит, опалубки, ЭППС, термовставок;
- спецификации кровли, зон кровли, мембран, геотекстиля, утеплителя, воронок;
- спецификации вентканалов Schiedel;
- любые таблицы, которые могут повлиять на смету, даже если непонятно, куда они
  относятся.

## Правило про штампы

Адрес проекта определяется по титульному листу / исходному загруженному комплекту.
Штампы отдельных листов могут быть ошибками оформления: проектировщики часто
копируют листы из других проектов и не правят адрес/шифр. Не отбрасывай страницу
только из-за другого штампа.

Если штамп отличается от титульного:

- запиши это в `page_map[].stamp_discrepancy_note`;
- добавь общее предупреждение в `extraction_warnings`;
- продолжай выписывать таблицы этой страницы по содержанию.

То же правило действует, если неверный адрес/объект/кадастровый номер встречается
в тексте пояснительной записки: зафиксируй расхождение, но не исключай данные.

## `legend_ref`

Если строка таблицы ссылается на легенду через штриховку/маркер/цвет, пиши:

```json
"legend_ref": {
  "marker_raw": "<штриховка диагональная / заливка / цвет / обозначение как видно>",
  "legend_text": "Несущие стены / перегородки / другой текст легенды",
  "legend_source": "PDF page <page_number>, лист <sheet_number>: легенда схемы"
}
```

`page_number` и `sheet_number` всегда бери из текущего проекта/листа. Не копируй
номер страницы из примера. Если легенды нет или маркер не нужен, ставь
`legend_ref: null`.

## Запреты

- Не создавай `target_code`.
- Не выбирай раздел сметы.
- Не суммируй строки, если в PDF нет строки "Итого".
- Не конвертируй единицы.
- Не исправляй ошибки проекта.
- Не сокращай таблицу до трёх колонок, если в PDF колонок больше.
- Не теряй ГОСТ/СТО/марки материалов, если они есть в строке.
- Не подставляй "логически похожие" значения из памяти или из других проектов.
