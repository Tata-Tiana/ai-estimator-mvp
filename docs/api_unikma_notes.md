# API УНИКМА: заметки и итог первого тестирования

Документ фиксирует, как прошел первый реальный тест API УНИКМА, какие данные удалось получить, где возникли затыки и что это значит для MVP AI-сметчика.

Дата тестирования: `2026-04-30`.

## 1. Назначение API для проекта

API УНИКМА в текущей архитектуре нужен не для расчета сметы целиком, а как источник:

- товарной номенклатуры;
- прайса;
- складов;
- остатков по конкретным товарам.

То есть УНИКМА API закрывает слой поставщика материалов:

```text
строка сметы -> найденный товар УНИКМА -> цена -> склад/остаток -> расчет закупки
```

Он не заменяет внутреннюю логику сметы:

- работы;
- услуги;
- коэффициенты;
- правила округления;
- накладные расходы;
- логистику;
- ручные проверки.


### `GET /GetNomenclatures/`

Статус: работает, но есть особенности формата и лимитов.

Что выяснилось:

- API возвращает не список напрямую, а JSON-объект с ключом `ArrayRef`;
- внутри `ArrayRef` лежит список товаров;
- старый тестовый клиент ожидал список напрямую и сначала ломался;
- клиент был поправлен: теперь извлекает `ArrayRef`.

Фактический формат:

```json
{
  "ArrayRef": [
    {
      "GUID": "...",
      "Code": "...",
      "Name": "...",
      "FullName": "...",
      "BaseEdName": "...",
      "Ed_Izmer": []
    }
  ]
}
```

Затык с большим лимитом:

- запрос `Limit=5000` вернул HTTP 200;
- но тело ответа оказалось невалидным JSON;
- из-за этого `response.json()` упал с `JSONDecodeError`.

Рабочий обход:

- грузить постранично;
- безопасный тестовый размер страницы: `Limit=100`.

Что было загружено:

- первые `3000` позиций;
- 30 страниц по 100 товаров.

Сохраненный объединенный файл:

```text
data/reference/unikma/nomenclature_combined_20260430_185526.json
```

### `POST /GetRemain/`

В рамках этого теста по кровельному фрагменту полноценно не прогонялся.

Причина:

- сначала нужно надежно получить GUID/код найденных товарных позиций;
- часть совпадений требует ручной проверки;
- многие строки сметы оказались работами или услугами, а не товарами.

## 7. Что не нашлось точно

Точные совпадения не найдены:

- `Пленка пароизоляция ТехноНИКОЛЬ 120 мкм, 150 м2/рул`;
- `Геотекстиль ТЕХНОНИКОЛЬ ПРОФ Кровля 300, 2x50м`;
- `Геотекстиль ТЕХНОНИКОЛЬ ПРОФ Кровля 150, 2x50м`;
- `Рейка прижимная алюминиевая 3м`;
- `Рейка краевая алюминиевая 3м`;
- `Аэратор кровельный PVC, 75x375`;
- `Устройство внутреннего водостока (ПВХ ф110мм)`.

Причины:

- в прайсе другие названия;
- часть товаров отсутствует;
- есть похожие аналоги, но они не являются точным совпадением;
- некоторые позиции являются смешанными: материал + работа.

Пример:

- по рейке нашлись похожие `планки прижимные`, но длина и назначение отличаются;
- подставлять их автоматически нельзя.

## 8. Что не является товаром УНИКМА

Эти строки нельзя напрямую считать через товарный прайс:

- `Установка воронки парапетной`;
- `Пробивка отверстий в стенах из газоблока толщ.400мм`;
- `Установка воронки кровельной`;
- `Подъем материалов автокраном`;
- `Логистика, и снабжение`;
- `Расходные материалы, амортизация инструмента`;
- `Вывоз мусора с объекта`.

Для них нужен внутренний слой сметной логики:

- база работ;
- ставки работ;
- правила расчета услуг;
- проценты/коэффициенты;
- ручная проверка.

## 9. Главный затык

Главный затык не в самом API, а в сопоставлении сметы с товарной базой.

Строка сметы часто не равна товару УНИКМА.

В смете встречаются:

- чистые материалы;
- работы;
- услуги;
- смешанные строки;
- укрупненные позиции;
- человеческие названия;
- единицы измерения, отличные от единиц продажи.

Прайс УНИКМА содержит:

- товарные названия;
- коды;
- цены;
- признак складского наличия;
- иногда не те бренды или модификации;
- иногда похожие, но не точные позиции.

Поэтому нужен отдельный слой `material matching`.

## 10. Рекомендуемая схема material matching

Для каждой строки сметы:

```text
1. Определить тип строки:
   material / work / service / mixed / allowance

2. Если это material:
   нормализовать название
   найти кандидатов в УНИКМА
   проверить бренд, размер, толщину, упаковку, единицу измерения
   выбрать лучший match
   рассчитать закупочную единицу
   посчитать сумму

3. Если это work/service:
   не искать в УНИКМА
   отправить в базу работ или правил сметы

4. Если mixed:
   разделить на материал и работу

5. Проставить статус:
   matched
   matched_needs_review
   not_found_exact
   not_material
   manual_required
```

## 11. Статусы сопоставления

Рекомендуемые статусы:

- `matched`
  - точное совпадение, можно считать автоматически.

- `matched_needs_review`
  - совпадение найдено, но есть риск:
    - другая упаковка;
    - нет на складе;
    - распродажа;
    - спорная конвертация единиц.

- `not_found_exact`
  - точное совпадение не найдено.

- `not_material`
  - строка является работой или услугой.

- `manual_required`
  - нужна ручная классификация.

## 12. Практический вывод для MVP

УНИКМА API можно использовать в MVP, но не как самостоятельный расчетчик.

Роль УНИКМА:

- дать актуальные товарные позиции;
- дать цены;
- дать склад/остатки;
- помочь с закупочной частью сметы.

Роль нашего MVP:

- извлечь строки сметы и проектные параметры;
- понять, что является материалом, работой или услугой;
- сопоставить материал с товаром УНИКМА;
- посчитать конвертацию единиц;
- пометить спорные места для человека;
- не считать автоматически то, что требует проверки.

Самая ценная следующая задача:

```text
сделать отдельный эксперимент material_matcher_v2
```

Он должен работать не по простому substring-поиску, а по нормализованным признакам:

- бренд;
- категория;
- материал;
- толщина;
- размер;
- упаковка;
- единица измерения;
- назначение;
- наличие/цена.

## 13. Что помнить при следующем запуске

- Не выводить API-ключ в консоль и логи.
- Для `GetNomenclatures` читать `ArrayRef`.
- Не запрашивать сразу `Limit=5000`, лучше идти страницами.
- Прайс Excel может быть полезнее для первичного поиска цен.
- Не считать работы и услуги через УНИКМА.
- Любую конвертацию `м2/м3/мп -> упаковки/рулоны/наборы` помечать как проверяемую.
- Если товар найден, но `Складской = Нет`, нужна ручная проверка.
- Если товар найден как `распродажа`, нужна ручная проверка.
