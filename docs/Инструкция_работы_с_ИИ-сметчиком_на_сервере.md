# Инструкция по работе с ИИ-сметчиком на сервере

Дата: 29.09.2026.

## 1. Что работает в первой версии

Первая версия принимает результат извлечения проекта в формате JSON, создаёт отчёт
для проверки, формирует промежуточную Google-таблицу, запускает семь готовых
калькуляторов и выдаёт итоговую смету в Excel.

Рабочие расчётные направления:

1. Земляные работы.
2. Фундаментная плита.
3. Гидроизоляция и утепление бортов.
4. Внешние и внутренние несущие стены, перемычки.
5. Плиты перекрытия и покрытия с динамическим количеством блоков.
6. Плоская кровля.
7. Вентиляционные каналы Schiedel.

Сервер пока не отправляет PDF в Claude или ChatGPT самостоятельно. Основной
production-маршрут начинается с готового JSON, полученного во внешнем ChatGPT-чате.

## 2. Начало работы

Отправить боту команду:

```text
/start
```

Бот вернёт краткую последовательность работы. Команда `/start` не создаёт job, не
запускает модель, не выполняет расчёты и не обращается к Google Drive.

## 3. Подготовка первого JSON

Во внешнем ChatGPT-чате нужно передать файлы проекта и получить extraction JSON.
Корневой объект JSON должен содержать как минимум:

```json
{
  "project_name": "полное название или адрес объекта",
  "source_files": ["КР1_ПРОЕКТ.pdf", "КР2_ПРОЕКТ.pdf"],
  "sections": {}
}
```

Поле `source_files` обязательно сохраняет реальные имена исходных PDF. По ним бот
определяет короткое название проекта для job и папки Google Drive. Например:

```text
КР-1_ТРЦ_01.07.2026.pdf
КР2_ТРЦ_30.07.2026.pdf
```

дают короткое название `ТРЦ`.

## 4. Первая загрузка JSON

Первый JSON нужно отправить боту как файл. Бот:

1. скачивает и проверяет JSON;
2. проверяет наличие поля `sections`;
3. извлекает короткое название из `source_files`;
4. создаёт новый `job_id`;
5. создаёт локальную папку job на сервере;
6. сохраняет исходный JSON;
7. формирует текстовый отчёт с замечаниями;
8. отправляет отчёт обратно в Telegram.

Пример `job_id`:

```text
trc_20260929_183000
```

## 5. Где хранится job на сервере

Каждый JSON-job получает отдельную папку:

```text
/home/calc/ai-estimator-mvp/
  experiments/chat_extraction_poc/outputs/<job_id>/
```

Пример полного пути:

```text
/home/calc/ai-estimator-mvp/experiments/chat_extraction_poc/outputs/trc_20260929_183000/
```

Внутри по мере работы появляются:

```text
extraction_output_bot_<дата_время>.json
code_notes_report_bot_<дата_время>.txt
review_workbook.xlsx
review_workbook_downloaded.xlsx
section_results/
estimate_<дата_время>.xlsx
```

Сессия текущего JSON-прогона хранится отдельно:

```text
/home/calc/ai-estimator-mvp/
  experiments/earthworks_review_to_calculator/data/telegram_extraction_sessions/<chat_id>.json
```

Реестр последних job пользователя и ссылок Google Drive:

```text
/home/calc/ai-estimator-mvp/
  experiments/earthworks_review_to_calculator/data/telegram_user_jobs/<chat_id>.json
```

## 6. Исправление JSON

Полученный от бота отчёт нужно вернуть в тот же ChatGPT-чат, где выполнялось
извлечение, вместе с промптом исправления. Исправленный JSON затем отправляется боту.

В течение двух часов следующий JSON в том же Telegram-чате считается исправленной
версией текущего job. Если нужно вернуться к старому job позднее, используется:

```text
/update_json <job_id>
```

Для явного начала другого проекта:

```text
/new_project
```

## 7. Создание папки Google Drive

После получения исправленного JSON бот создаёт в рабочей папке Google Drive отдельную
папку проекта. Название формируется из имён исходных PDF и даты создания job:

```text
<НАЗВАНИЕ ПРОЕКТА> — <ДД.ММ.ГГГГ>
```

Пример:

```text
ТРЦ — 29.09.2026
```

Внутри создаётся промежуточная таблица:

```text
Проверка — ТРЦ — 29.09.2026
```

При команде `/recreate <job_id>` новая версия Google-таблицы создаётся в той же
папке проекта. Новая папка для одного и того же job не создаётся.

Если `source_files` отсутствует или из имён файлов нельзя выделить название, бот
использует имя загруженного JSON, затем `project_name` как последний fallback.

## 8. Промежуточная Google-таблица

Перед публикацией бот собирает локальный `review_workbook.xlsx`. Основные листы:

- `01_Проверка проекта` — параметры, объёмы и исправления сметчика;
- `01-1_Ручные строки (справочник)` — значения, которых нет в проекте;
- `02_Цены себестоимости` — прайс и ручная замена цены;
- `03_Детали объемов` — извлечённые строки и источники;
- `04_Инструкция`;
- скрытые технические листы parser-кандидатов и сырых данных.

Цены сначала читаются из Google price registry. Локальный файл
`price_registry_filled_v4.xlsx` служит резервным snapshot.

Сейчас таблица публикуется с режимом `anyone_writer`: любой человек со ссылкой может
её редактировать. Сам job доступен через команды бота только создавшему его
Telegram-чату и администратору.

## 9. Проверка сметчиком

В Google-таблице сметчик:

1. проверяет найденные объёмы;
2. исправляет спорные или отсутствующие значения;
3. заполняет ручные строки;
4. проверяет включение конструкций;
5. проверяет цены на листе `02_Цены себестоимости`;
6. при необходимости вводит исправленную цену.

Скачивать таблицу вручную не требуется. После проверки нужно отправить:

```text
/build <job_id>
```

## 10. Сборка сметы

После `/build` сервер:

1. проверяет право пользователя на job;
2. скачивает текущее состояние Google-таблицы в Excel;
3. запускает все семь расчётных направлений;
4. сохраняет результаты каждого раздела в `section_results/`;
5. при ошибках возвращает единый список проблем;
6. при успехе собирает итоговый Excel;
7. сохраняет Excel в папке job;
8. отправляет Excel пользователю в Telegram.

Если хотя бы один обязательный раздел не рассчитался, частичная смета не выдаётся.
Сметчик исправляет Google-таблицу и повторяет `/build <job_id>`.

## 11. Устройство итогового Excel

В итоговой смете:

- `A:I` — левая часть, которая выводится на печать;
- `J:O` — правая расчётная часть себестоимости;
- `P:V` — техническая серая зона;
- строки и итоги связаны формулами;
- итоги материалов и работ пересчитываются в Excel;
- итоги разделов и общий итог также являются формулами;
- печатная область ограничена колонками `A:I`;
- серые колонки не выводятся на печать.

Итоговый Excel пока сохраняется на сервере и отправляется через Telegram. В Google
Drive автоматически размещается промежуточная таблица; загрузка итогового Excel в
папку Drive в текущую версию не входит.

## 12. Ограничение клиентской части

В первой версии левая часть в основном зеркалит значения себестоимости из правой
части. Полный алгоритм клиентских цен с коэффициентом `1,32`, перераспределением
стоимости работ, НР, СП, ЗСР и техническим надзором относится к следующему этапу и
пока не работает на сервере.

## 13. Как работает приложение на сервере

Приложение установлено в:

```text
/home/calc/ai-estimator-mvp
```

Основные параметры:

- процесс работает от пользователя `calc`;
- зависимости находятся в отдельном `.venv` проекта;
- процессом управляет `calc.service`;
- сервис включён в автозапуск;
- при аварийном завершении systemd повторяет запуск через 10 секунд;
- Telegram API вызывается через HTTP-прокси;
- Google API работает напрямую;
- секреты находятся вне проекта в закрытом `calc.env` с правами `600`;
- локальный бот на Mac остановлен, серверный является единственным poller.

Команда `/start` и обычные пользовательские операции доступны всем пользователям,
потому что сейчас установлено `ALLOW_ALL_USERS=true`. Административные команды
ограничены списком `TELEGRAM_ADMIN_CHAT_IDS`.

## 14. Полная схема

```text
PDF проекта
  ↓
внешний ChatGPT-чат: извлечение
  ↓
первый JSON
  ↓
Telegram-бот: job + отчёт замечаний
  ↓
внешний ChatGPT-чат: исправление JSON
  ↓
исправленный JSON
  ↓
локальный review_workbook.xlsx
  ↓
папка проекта и промежуточная Google-таблица
  ↓
проверка сметчиком
  ↓
/build <job_id>
  ↓
семь калькуляторов
  ↓
итоговая смета Excel
  ↓
файл отправляется пользователю в Telegram
```
